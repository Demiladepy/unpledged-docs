## What Unpledged does

A small business (the **SME**) borrows against an unpaid invoice. Before
lending, the lender needs to know the invoice is **unpledged**: no other lender
already holds it as collateral. Unpledged answers that question without
showing the lender the SME's invoices, and the ledger itself refuses a second
pledge of the same invoice.

Lenders that compete with each other cannot share their loan books, so none of
them can see whether an invoice is already financed elsewhere. That gap is how
the same receivable gets pledged twice. The 2025 collapses of First Brands and
Tricolor involved billions of dollars in receivables and collateral that had
allegedly been pledged to more than one lender.

Unpledged enforces two guarantees in its Daml contracts:

| Guarantee | How it is enforced |
| --- | --- |
| **Privacy.** A lender sees a summary of the SME's settled invoices, never the invoices themselves. | `UnpledgedAttestation` carries only a count, a total, and an on-time flag. Lender A is an observer of the attestation, never a stakeholder of the `Invoice`. |
| **No double pledge.** An invoice can be financed once. | `PledgeRegistry` stores a canonical reference for each pledged invoice. A second `RecordPledge` for the same reference fails its assertion, so Canton rejects the whole transaction at commit time. |

## Who this documentation is for

- **Developers evaluating Canton or Daml** who want a small, complete example
  of a privacy-preserving workflow they can run and read in an afternoon.
- **Fintech and trade-finance engineers** exploring how selective disclosure
  can replace manual collateral checks.
- **Contributors** who want to run the app against a real Canton DevNet
  participant and change the flow.

You should be comfortable with a terminal and Node.js. You do not need to know
Daml to finish the quickstart.

## How it fits together

```text
React UI (Vite)  ──▶  /api/ledger + /api/token proxies  ──▶  Canton DevNet
                      (client secret stays server-side)       JSON Ledger API v2
```

- **Daml contracts** (`daml/`): the `Invoice`, `Attestation`, and `Financing`
  modules, built with Daml SDK 3.4.11 for Daml-LF 2.1.
- **Frontend** (`frontend/`): a React app with five views: Privacy, SME,
  Lender, Blocked, and Full flow.
- **Ledger scripts** (`frontend/server/`): command-line scripts that allocate
  parties, create contracts, and verify privacy against DevNet.

The app runs in two modes:

| Mode | What you need | What happens |
| --- | --- | --- |
| **Mock** (default) | Node.js 22 or later | Ledger calls are answered from local mock data. Use it to learn the flow. |
| **Live DevNet** | A Canton DevNet client secret | Every action is a real command on the Five North DevNet validator. |
